# Glimmer IDE Shell — Implementation Plan (Rounds A + B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Make Glimmer Control Center usable the way Cursor/Claude Code are — see the code, ask about it, act on it — without giving up the guarantee that VERIFIED means something actually ran.

**Architecture:** The Control Center is a React control surface over the Glimmer orchestrator, not an editor. Round A adds a read-only code surface (file tree + viewer) reusing the diff screen's hand-rolled highlighting. Round B turns a selection in that surface into (i) a read-only question to the session assistant and (ii) a one-click scoped session, so the composer's ceremony collapses without bypassing any gate.

**Tech Stack:** TypeScript, React 18, react-query, react-router, Express gateway, Vite/Vitest. Tauri 2 shell.

**Spec:** V7 architecture doc `/Users/danielqazi/AI/GLIMMER_AGENT_OS_ARCHITECTURE_V7.md` (§14 diff review, §20 read-only assistant, §35 approval boundary) plus the campaign ledger `.superpowers/sdd/2026-08-22-v7-full-closure/progress.md`.

## Global Constraints

- No new npm deps for the editor surface. The diff screen already hand-rolls syntax highlighting with `--tok-*` tokens — reuse it. Do not add Monaco/CodeMirror/Prism/highlight.js.
- Honesty rules, zero tolerance: never render a value that was not produced (`Unavailable`/`NOT_RUN` over a guess); provenance labels stay accurate; a read that failed says so.
- The assistant stays architecturally read-only: no `tools`/`functions` field in its requests (see `server/src/lib/sessionAssistant.ts` — the guarantee must not depend on the model obeying a prompt).
- Nothing in Round A or B may write files, apply model output directly, or bypass the orchestrator. All repository mutation continues to go through a session: contract → gates → verification → human diff review.
- Filesystem endpoints are read-only and contained; reuse the containment discipline established by `GET /api/fs/dirs` (realpath-then-contain on both boundary and path). Reviewed at security tier.
- `npm run build && npm run test` green from repo root; tests follow existing conventions.

## Round A — IDE shell (read-only code surface)

### Task A1: File content endpoint

**Files:**
- Modify: `server/src/routes/workspaces.ts` (already owns `GET /api/fs/dirs`)
- Test: `server/src/routes/workspaces.test.ts`

`GET /api/fs/file?path=…` returning the text content of one file plus its metadata (size, whether it was truncated, detected language from extension).

- Same containment as `/api/fs/dirs`: realpath both the boundary and the target, re-check containment after resolution, reject traversal/absolute escapes/symlink escapes.
- Cap the returned bytes (large-file ceiling) and say so honestly in the response rather than silently truncating.
- Refuse non-regular files (device, fifo, socket) and binary content — detect binary by NUL sniffing, return an honest "binary file, not shown" rather than garbage.
- Honest status codes; never leak the existence of out-of-boundary paths through differing errors.

### Task A2: File tree

**Files:**
- Create: `web/src/components/explorer/FileTreeScreen.tsx` (+ test)
- Modify: `web/src/components/layout/AppShell.tsx` (navigation entry)

Lazy directory expansion via `GET /api/fs/dirs` rooted at the active workspace, matching the existing sidebar/design conventions. Empty and error states are explicit, never a silent blank.

### Task A3: Code viewer

**Files:**
- Create: `web/src/components/explorer/CodeViewer.tsx` (+ test)
- Modify: the diff screen's highlighting module so both consumers share one tokenizer (extract if it currently lives inside `DiffReviewScreen.tsx`).

Read-only viewer with line numbers and the shared highlighting. Handles: truncated file notice, binary notice, unreadable file. No editing affordances — this is a viewer, and pretending otherwise would be dishonest UI.

### Task A4: Open-from-anywhere wiring

**Files:**
- Modify: `web/src/components/repository/RepositoryMapScreen.tsx`, `web/src/components/system-explorer/SystemExplorerScreen.tsx`, `web/src/components/diff/DiffReviewScreen.tsx`

Clicking a path anywhere (repo map entry, doc-graph node, diff file header) opens it in the viewer at the relevant line where a line is known.

## Round B — ask and act from context

### Task B1: Ask about a selection (read-only)

**Files:**
- Modify: `web/src/components/session/SessionAssistant.tsx`, `server/src/lib/sessionAssistant.ts`, `server/src/routes/sessions.ts`

Select lines in the viewer → ask the assistant with that file/selection as evidence. The selection is passed as evidence text, clearly labelled with its provenance (which file, which lines). The assistant request keeps its no-tools guarantee. Works with no active session (repo-context question, not session Q&A) — if that requires a separate route from the session-scoped one, add it rather than faking a session.

### Task B2: Act from a selection (one-click scoped session)

**Files:**
- Modify: `web/src/components/explorer/CodeViewer.tsx`, `web/src/components/task-composer/NewTaskScreen.tsx`

From a selection: type one sentence → a session is created with `scope.package = "files"`, `scope.paths` pre-filled with that file, objective from the sentence, verification defaulted from task intelligence's suggestion. The composer opens pre-filled rather than the session starting behind the user's back: one review click, then run.

Every gate still applies — this task changes only how a contract is composed, never what governs it.

### Task B3: Live file view during a session

**Files:**
- Modify: `web/src/components/session/ActiveSessionScreen.tsx`, `web/src/components/explorer/CodeViewer.tsx`

While a session runs, a `file_changed` event for the open file refreshes the viewer, so the user watches edits land instead of waiting for the terminal diff. Read-only; the authoritative accept/reject stays in diff review.
